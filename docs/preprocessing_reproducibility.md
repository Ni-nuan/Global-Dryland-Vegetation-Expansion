# Preprocessing reproducibility boundary

## Vegetation threshold/reprojection

The historical executable `TIF_yuzhi.py` has been recovered and its SHA-256 matches the audited provenance record. It is released in reusable form as:

`src/01_vegetation_expansion/threshold_rasters.py`

The refactor changes configuration handling, not the locked raster operation:

- scale the source index if configured;
- `value <= threshold -> 1` (below-threshold / non-vegetated);
- `value > threshold -> 0` (vegetated);
- preserve NoData separately;
- reproject the binary raster with nearest-neighbour resampling;
- target EPSG:8857 at 500 m.

Some production TIFF processing was also performed in ArcGIS Pro. Therefore this script provides an executable reconstruction of the audited operation, while the repository does not claim that every production raster was generated by this exact Python invocation.

## Raster/netCDF to hexagon tables

The original scripts used to extract several environmental raster/netCDF products to the 100-km² hexagon-year tables are no longer available. They are not recreated from assumptions. Where required, the public workflow begins from selected processed hexagon-level inputs documented in `docs/data_inventory.csv`.

## EVI threshold provenance

The supplied GEE EVI annual-maximum preprocessing code is retained. The executed EVI threshold value is not recoverable from the current code archive, so the repository does not assign an invented value. `configs/vegetation/evi.yaml` is intentionally configured to start from existing thresholded EVI rasters.

## Configuration versus method

YAML files under `configs/vegetation/` change only product/threshold/path/spatial-scale parameters. The core geometry, aggregation and trend calculations remain in one shared engine.
